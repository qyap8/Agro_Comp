# IrrigationHMI (UX update)

## Что обновлено

- Кнопки и элементы управления уменьшены (шрифты не уменьшались).
- Добавлены понятные иконки LVGL (`LV_SYMBOL_*`) в Home/Zones/Settings.
- Wi-Fi вынесен в отдельное всплывающее меню (modal):
  - ввод SSID/пароля,
  - статус подключения,
  - отображение текущего IP для входа в web UI.
- На web-интерфейс добавлен полноценный базовый функционал, эквивалентный экрану:
  - изменение каналов,
  - rescan,
  - Wi‑Fi настройки,
  - смена языка.

## Плавность и частичная перерисовка

Чтобы убрать «плавание», экран больше не чистится целиком при каждом refresh:
- Zones: перерисовка структуры только при смене топологии модулей/каналов,
  а состояние каналов обновляется точечно только у изменившейся кнопки.
- Home: карточки модулей пересоздаются только при изменении топологии.

Это снижает заметные рывки при скролле и кликах.

## Клавиатура (popup)

Клавиатура общая для всего UI:
- появляется снизу при фокусе на поле,
- резервирует нижний отступ контейнера,
- поле ввода прокручивается в видимую область,
- скрывается по Ready/Cancel/Defocus.

## Шрифты Español

В код добавлен безопасный хук для кастомного мульти-языкового шрифта:
- если существует `ui/fonts/lv_font_multilang_18.h`, шрифт будет применён автоматически.
- если файла нет, используется fallback (текущие системные шрифты).

Рекомендуется сгенерировать файл шрифта через LVGL Font Converter с диапазонами:
- Latin + Latin-1 Supplement.

И положить его в:
- `IrrigationHMI/ui/fonts/lv_font_multilang_18.h`
- `IrrigationHMI/ui/fonts/lv_font_multilang_18.c`


## Таймаут отключения экрана

Добавлена настройка `Screen timeout` в Settings:
- Off
- 30 sec
- 60 sec
- 120 sec
- 300 sec

Логика:
- при неактивности дольше таймаута экран гасится (чёрный overlay),
- при касании тачскрина экран сразу просыпается.


## Виджеты на первом экране

На Home добавлены виджеты:
- текущее время (HH:MM),
- день недели,
- краткий погодный виджет (облегчённый, без внешнего HTTPS-запроса).

Примечания:
- время синхронизируется через NTP при подключении к Wi‑Fi;
- погодный блок оставлен как облегчённый placeholder для экономии flash-памяти.

## Оптимизация размера прошивки и что «весит» больше всего

Что уже облегчено в этой версии:
- убраны языки RU/HY (оставлены только EN/ES),
- убран runtime-поллинг погоды через HTTP/TLS,
- web-страница упрощена до компактного viewer,
- удалены неиспользуемые weather-структуры из `SystemState`.

Что обычно занимает flash больше всего в таком проекте:
1. **LVGL + драйверы дисплея/тача** (крупные библиотеки, таблицы, виджеты).
2. **Wi‑Fi/WebServer стек** (сетевые компоненты и HTTP обработчики).
3. **Большие строковые литералы** (HTML/JS, локализация, длинные логи/форматирование).
4. **C++ STL/`String`-heavy код** (доп. шаблоны/хелперы линковщика).

Практические шаги, если нужно ещё уменьшить размер:
- выключить или минимизировать встроенный web UI (оставить только REST API),
- сократить JSON поля `/api/state`,
- держать только реально используемые экраны в `all_sources.cpp`,
- уменьшить количество/длину `lv_label_set_text_fmt` строк,
- при необходимости отключить редко используемые LVGL-фичи в `lv_conf.h`.

## Поможет ли переход на ESP-IDF?

Коротко: **иногда да, но не гарантированно сильно**.

Почему может стать лучше:
- ESP-IDF даёт более тонкий контроль над компонентами (можно отключить лишние),
- можно жестко ограничить набор включаемых модулей через `sdkconfig`,
- проще сделать build-профиль «только нужное».

Почему может почти не измениться:
- LVGL/драйверы дисплея всё равно останутся крупными,
- Wi‑Fi + HTTP стек в любом случае занимает заметный объём,
- если функционал тот же, выигрыш часто умеренный.

Итог: переход на ESP-IDF имеет смысл, если вы готовы заниматься компонентной настройкой и сборкой вручную.
Для быстрого результата в Arduino-проекте чаще эффективнее сначала урезать UI/web-функции и строки.
